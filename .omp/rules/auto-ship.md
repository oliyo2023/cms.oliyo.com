# 任务收尾：自动提交并推送

本仓库约定：**编码代理完成一次会改动文件的任务后，自行提交并推送，不需要用户开口。**

## 何时执行

- 任务改动了工作区文件（新增 / 修改 / 删除）→ 收尾时执行下面流程。
- 只读任务（回答问题、调研、解释代码、plan 模式）→ 不提交。
- 用户明确说了不要提交 / 稍后再说 / 正在批量重构中 → 不提交，并在回复里说明已跳过。
- 提交失败或推送失败 → 不能静默放过，必须在回复里写清楚卡在哪一步、本地是否已有提交。

## 怎么做

固定使用仓库脚本，**不要手工敲 `git add` / `git commit` / `git push`**：

```
pnpm ship -m "<提交说明>" -- <本次改动的文件...>
```

- `-m` 写提交说明：一句话讲清「改了什么、为什么」，与仓库既有提交风格一致（中文、祈使/陈述皆可，不必加 `feat:` 前缀）。
- `--` 之后逐个列出**本次任务实际改动的文件**。这是硬要求：本仓库存在并发编辑，`git add -A` 会把别人未完成的改动一起推上去。
  - 不确定改过哪些文件时，用 `git status --short` 核对后再列。
- 脚本自己会跑 `pnpm typecheck`，不通过就中止，不会提交。**不要用 `--skip-checks` 绕过门禁**，除非用户明确要求。

## 边界

- 脚本拒绝暂存 `.env*`、`.dev.vars`、`dev-data/`、`.wrangler/`、`.commandcode/`、`*.pem`、`*.key` 等敏感路径；被拒绝时不要改用 `git -f`，而是确认这些文件本就不该入库。
- 提交内容只包含本次任务的改动；不顺手把无关的文件、格式化、清理一起提交。
- 一个任务一个提交；不要把多个不相关的改动塞进同一条提交说明。
